# 架构与协议摘要

完整线协议见根目录 [`PROTOCOL.md`](../PROTOCOL.md)，本文是给新读者和贡献者的速览。

## 总体结构

```
┌────────────┐        UDP 47731（单通道）        ┌────────────┐
│  Android   │  ◄═══ 音频 + 发现 + 握手 + 保活 ══► │  PC（多台） │
│  手机 App   │        WiFi / USB 共用同一协议      │ Windows 原生 │
└─────┬──────┘                                    │ Linux: pc/   │
      │ 蓝牙/有线耳机（系统音频路由）               └────────────┘
      ▼
   耳机出声 / 耳机麦克风回传
```

- 一台手机同时与多台 PC 各保持一个会话（session），协议对 PC 数量无上限。
- 手机麦克风帧**扇出**到所有开启接收的 PC；各 PC 的声音在手机端按各自音量**混音**后播放。
- 耳机场景不走网络协议：耳机连手机后属于手机的系统音频设备，由手机端在系统路由层选用出声/收声设备，网络侧无感知。

## 线协议要点

- **通道**：单个 UDP 端口 `47731`，承载发现信标、配对握手、保活与音频；WiFi、USB 网络共享、`adb forward` 三种承载共用同一套代码路径。
- **包头**：16 字节大端。魔数 `0x5041`、包类型、标志位（编码/采样率码）、序号（每方向每会话独立）、微秒时间戳（PING/PONG 回显测 RTT）。
- **音频**：PCM16 单声道，10 ms 一帧（48k 时 960 B）。采样率三档 48k/24k/16k 全局自适应：任一会话丢包 > 5% 或抖动 > 15 ms 就逐档下调，全部会话干净约 30 s 后升回。Opus 编码位已在协议头预留，当前版本未启用。
- **抖动缓冲**：每会话独立，目标深度按实测抖动钳制在 20–60 ms；缺帧以静音 conceal 并计入丢包统计。
- **保活**：每会话 1 s 一次 PING/PONG；5 s 无包判死链，自动重连。

## 发现与配对

- **发现三路并行**：PC 每秒广播 BEACON（UDP）、mDNS 服务类型 `_airbridge._udp`（历史命名，协议标识保持不变以兼容已发布版本）、BLE 近感广播（服务 UUID 见 PROTOCOL.md，仅做近感存在性感知，音频不走 BLE）。
- **身份**：每个端点有持久 `deviceId`；每台 PC 持有一个配对令牌 `token`，线上只出现其 SHA-256（`tokenHash`），令牌本体只在配对成功的 HELLO_ACK 里经局域网传一次。
- **配对方式**（优先级从高到低）：附近列表点选（HELLO 带 pairTap，PC 侧确认）、扫 PC 屏幕二维码、输入 PC 显示的 6 位配对码（广播 + 已知 IP 单播扇出双通道查找，防 AP 隔离丢广播）、手动输入 IP 兜底。
- **验证码**：配对后由 `SHA-256(token + ":" + 手机deviceId)` 派生 6 位验证码，两端同屏显示，用户核对一致才落盘保存配对关系。
- **漫游恢复**：网络变化（Mesh 节点切换、IP 变更）时，端点按 `deviceId` 用最新一次 sighting 的地址重新对准会话，不信任缓存 IP；PC 端收到已连接手机从新地址发来的包时立即迁移发送目标。

## 音频链路（手机端）

- 采集：`VOICE_COMMUNICATION` 音源 + 主麦优选（setPreferredDevice/方向），约 100 Hz 高通滤除桌面传导低频噪声；麦克风模式三档（语音通话 / 高清拾音 / 自动）在会话边界切换，会话内配置不翻转。
- 回声处理链（顺序固定）：平台 AEC → 自研 NLMS（参考信号取**最终混音渲染点**，即实际写进 AudioTrack 的帧）→ 双讲检测冻结/封顶抑制 → 啸叫守卫。手机本地麦克风声音绝不回放到本机播放链（混音输入只有网络下行帧），PC 侧另有路由冲突阻止 + 相关度检测拦截自身声音绕回。
- 播放：默认扬声器，输出设备按系统真实设备枚举选用（扬声器/听筒/蓝牙/有线耳机），插拔实时刷新；蓝牙 SCO 等设备采样率差异在设备边界重采样，不重协商网络采样率。

## 更新

- 清单 `update.json`（仓库根目录即托管地址，两端共用）：含 android/windows 两条目，各带 version、下载 URL、SHA-256、更新说明。
- 两端同版本成套发布；握手交换 `appVersion`/`protoVersion`，不一致时明确提示先更新哪一端，不静默失败。
- 客户端下载后先验 SHA-256， mismatch 即拒绝安装；清单地址可在 App 设置中修改（可迁到自有服务器）。

## Windows 音频落点

- 原生端用 WASAPI 枚举/路由系统音频设备；手机麦克风要被会议软件选到，需要一个虚拟音频设备：优先识别自有品牌驱动端点「声音接力 SoundRelay 虚拟音频设备」（`driver/`，当前测试签名），未装时回退 VB-CABLE。
- 路由防环：渲染与采集若选中同一条虚拟线缆的两端（会把手机麦克风原样绕回），原生端会判定冲突并阻止发送。
