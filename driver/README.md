# 声音接力 SoundRelay 虚拟音频驱动 — 测试签名版（路线 A，自用）

安装后，Windows 声音设置里会出现声音接力自己的音频设备：

- 输出：**扬声器 （声音接力 SoundRelay 虚拟音频设备）**
- 输入：**麦克风 （声音接力 SoundRelay 虚拟音频设备）**

基底是微软官方 Simple Audio Sample 驱动（一个扬声器 + 一个麦克风端点），改动清单见 `CHANGES.md`，路线与签名背景见 `../work-v2/virtual-driver-research.md`。

> ⚠️ **先说清三件事（诚实标注）**
> 1. **本包是源码 + 脚本，不含编译好的 .sys。** 我们的构建沙箱是 Linux，WDK 工具链只有 Windows 版，`.sys` 必须在你的 Windows 机器上编译（一键脚本会自动完成这一步，你不用手动操作）。我在 Linux 侧已核完的是：上游源码完整拉取、品牌字符串改完且与上游 diff 只有 2 个文件、测试证书生成并验过 EKU、三个脚本逐行复核。**编译/安装/界面显示未在 Windows 上实测过**，第一次跑请按「预期」对照，跑不通把脚本输出发回来。
> 2. **测试签名 = 必须开 Windows 测试模式**：桌面右下角会有 "Test Mode" 水印，且 **Secure Boot 必须关闭**（见下方红色警告）。这只适合自己的机器自用，不能给别人装。产品化走 EV + 微软证明签名（路线 B），代码同一份。
> 3. **本阶段只解决「品牌端点出现」**：驱动装上后两个端点会被系统识别、可被选中；但样本驱动的音频通路尚未与 SoundRelay App 打通（播到虚拟扬声器的声音不会自动去手机、虚拟麦克风也不会有手机的声音）——那是下一步开发（共享环形缓冲，见调研报告 §2.2）。在打通前，App 继续走 VB-CABLE 兜底，不受影响。

## ⛔ 前置条件（缺一不可）

在**将要编译 + 安装的同一台 Windows 机器**上（建议先用虚拟机练一遍，驱动出问题可快照回滚）：

1. **Visual Studio 2022**，勾选「使用 C++ 的桌面开发」工作负载。
2. **Windows SDK + WDK**（版本与 VS 匹配，当前主线 10.0.26100.x）：从微软官网 Download the WDK 页面装，先 SDK 后 WDK。装完确认存在：
   - `C:\Program Files (x86)\Windows Kits\10\bin\<版本>\x64\signtool.exe`
   - `C:\Program Files (x86)\Windows Kits\10\Tools\<版本>\x64\devcon.exe`
3. **Secure Boot 必须关闭**（最重要的一步）：
   - 检查：管理员 PowerShell 运行 `Confirm-SecureBootUEFI`，返回 `True` = 还开着。
   - 关闭：重启进 UEFI/BIOS 设置 → Secure Boot 设为 Disabled → 保存退出。（开着 Secure Boot 时测试模式无法生效、测试签名的驱动会被直接拒载，`install.bat` 会检测并拦下。）
   - 注意：若系统盘开了 BitLocker，改 Secure Boot/测试模式可能触发恢复密钥询问，手边备好恢复密钥再动手。

## 唯一要做的事：双击 `一键安装.bat`

包里脚本不少，但**你只需要双击 `一键安装.bat` 这一个文件**，其余全自动，不用理解任何内部细节：

1. 它自己弹 UAC 提权，你点「是」；
2. 它检查 Secure Boot：还开着就停下来，把要做的事写在屏幕上（去 BIOS 关掉，再双击一次即可）；
3. 没编译过就自动编译 + 测试签名（第一次约几分钟，期间的英文输出不用管）；
4. 自动导入测试证书、打开测试模式；
5. 它会问你是否现在重启（选 Y）——**这是唯一一次重启**；重启后登录 Windows，它会自己接着把设备装完，你什么都不用点；万一重启后没自动弹出来，再双击一次 `一键安装.bat` 就行，它认得出做到哪一步了、会从断点继续；
6. 自动创建设备、安装驱动、当场验活，最后打印 SUCCESS 并告诉你去哪里看新设备。

> 脚本窗口里是简短英文（.bat 文件嵌中文在某些系统上会解析出错，这是刻意的），上面每一步在屏幕上长什么样、写着什么，本节就是对照翻译。

**为什么不能像 UU 那样装完直接用？** UU 的驱动带微软官方签名，所以能静默安装；内核驱动没有微软签名，就只能走测试签名，而 Windows 规定测试模式必须重启一次才生效、生效后桌面带测试水印。这是签名问题、不是脚本能绕过的，路线 B（EV 证书 + 微软证明签名）落地后，同一套东西就能零打扰安装。

**Windows 强加、谁都绕不开的只有两件**：重启一次；测试模式水印会一直在（路线 A 自用的代价）。其余步骤已经全部自动化。

### 手动方式（可选，一般不用）

一键脚本内部复用的就是这套分步逻辑，只有要逐步排障时才用：`build-and-sign.bat` 编译 + 测试签名（测试证书 `cert\driver-test-cert.pfx`，密码 `AirBridge-Test-2026`，TEST ONLY，已写明在 `cert\CERT-README.txt`，产品版会整体删除）→ `install.bat` 第一段导入证书 + 开测试模式 → 重启 → `install.bat` 第二段用 devcon 按硬件 ID `ROOT\SimpleAudioSample` 创建设备节点并装驱动。

### 成功长什么样（预期界面）

- **设置 → 系统 → 声音**：输出设备列表里出现「扬声器 （声音接力 SoundRelay 虚拟音频设备）」，输入设备列表里出现「麦克风 （声音接力 SoundRelay 虚拟音频设备）」——形态与 UU远程的「扬声器 (UU远程虚拟音频设备)」完全一致（前半是系统按引脚类别给的本地化名，后半括号内是我们在 INF 里写的设备名）。
- **设备管理器 → 声音、视频和游戏控制器**：出现「声音接力 SoundRelay 虚拟音频设备」，提供商 SoundRelay，无黄色感叹号（有感叹号多半是测试模式没生效或签名没对上，把 `devcon status` 的输出发回排查）。

## SoundRelay App 如何识别这对端点（后续集成口径）

PC 端 App（Avalonia/NAudio）枚举音频端点时，**按友好名包含「声音接力 SoundRelay 虚拟音频设备」匹配**：输出/输入各命中一个即认定自有驱动在位，走驱动通路（通路打通后启用）；**匹配不到就自动回退现有 VB-CABLE 逻辑**，并在界面提示「未安装声音接力虚拟音频设备」。所以本驱动没装、装坏、被卸载，App 都能照常工作，只是用回 VB-CABLE。

## 卸载

右键 **`uninstall.bat` → 以管理员身份运行**：移除设备节点 → 从驱动商店删除驱动包；然后会**逐项询问**是否一并删除测试证书、是否关闭测试模式（关测试模式选 Y 后需重启生效；若机器上还有其他测试签名驱动，选 N 保留）。

## 常见问题预期

- **重启后没有自动继续**：再双击一次 `一键安装.bat` 即可——它是按状态推进的，会自动跳过已完成的步骤、从断点继续，不会重复劳动。
- **build 找不到 signtool/inf2cat**：WDK 没装或版本目录不同——脚本按 `Windows Kits\10\bin\<最高版本>` 搜索，确认 WDK 安装完整。
- **devcon 找不到**：个别 WDK 版本 devcon 路径不同，install.bat 会退而用 pnputil 只暂存驱动包并打印手动命令 `devcon install <inf 路径> ROOT\SimpleAudioSample`，照着执行即可。
- **设备带感叹号 / 代码 52**：签名验证没过——多半是没重启进测试模式、或证书没导入成功，重跑 install.bat 两段流程。
- **蓝屏风险提示**：这是微软样本的成熟代码、改动仅字符串与一行类别 GUID，风险低；但内核驱动无小事，第一次请先在虚拟机或非主力机上验证。
