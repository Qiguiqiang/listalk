# 听说 LisTalk · 安卓端 UI 产品级改版说明

配套原型：`preview_android.html`（可点，左侧目录直达任意状态；打开默认停在欢迎页，按首启顺序往下点即是完整新用户路径）。
标准：对标 AirDrop / Spotify Connect 一类消费级连接型产品——每个状态都被设计过、每句文案说人话、每屏只有一个主操作。
本轮只出原型与说明，不动 App 代码；评审通过后再落地（沿用桌面端「原型先行」流程）。

---

## 一、信息架构：从「一页到底」改为「一条主线」

现版安卓 UI 是一个 1551 行的单布局长页面：状态头、四种横幅、状态大卡、设备区、添加电脑卡、通道卡、主按钮全部纵向堆在同一屏滚动，设置/发现/扫码/输码/配对确认是五个靠可见性切换的全屏覆盖层。新版改为明确的主线导航：

```
首启：欢迎 → 权限说明(麦克风) → 权限说明(发现设备) → 设备页
日常：设备页(搜索/列表/空) → 连接中 → 会话页 ⇄ 守卫暂停 / 断线重连
支线：配对确认 · 输配对码 · 设置 · (底部弹层) 路由选择 / 添加网段 / 更新全流程
```

会话页成为连接后的唯一中心（状态、通道、路由、断开都在一屏内闭环），设置是独立页，弹层只做单件事。用户在任何一屏都能回答三个问题：我在哪、现在什么状态、下一步点哪。

## 二、逐屏设计说明

### 1. 欢迎页（新增）
- 一句话讲清产品本质（与 FB 定的口径一致：「让影音在电脑、手机和耳机之间自由接力」），电脑→声波→手机的动效图，无文字墙。
- 先给预期再要权限：底部明示「下一步会先说明为什么需要两个权限，再向你申请」——消费级产品的信任建立方式。
- 主操作唯一：开始使用。

### 2. 权限说明 ×2（新增，先讲为什么再申请）
- 麦克风：三条勾选式说明——为什么必须（本职就是送声音）、何时才收音（点连接后、断开即停、状态栏有指示）、数据去向（只发自己配对的电脑、不上传不保存）。按钮文案是动作本身「好，允许麦克风」，点了才触发系统弹窗；「暂时跳过」明示后果（连接时还会再问），不堵死路。
- 发现设备：说清安卓的「附近设备/Wi-Fi」权限是系统对局域网搜索的硬要求，并正面回应用户最可能的顾虑——「和定位无关，不读取、不记录位置」；拒绝的替代路径直接给：用配对码添加（按钮直达输码页）。

### 3. 设备页 · 搜索中
- 雷达呼吸动画 + 一句状态话（同时搜本网段与已添加网段），不再是转圈菊花配「请稍候」。
- 已配对设备在搜索时就先出现（离线也显示并标注上次连接时间），附近列表用骨架屏占位——布局从第一帧就稳定，不跳动。

### 4. 设备页 · 发现列表（主页）
- 分组：已配对（在线直接给「连接」药丸按钮，整卡可点）/ 附近（点卡去配对）。
- **跨网段设备带天蓝色标签「跨网段 · 192.168.99.x」（FB-6）**，底部一行注明来源（设置中添加的网段），让用户理解「为什么隔着路由器也能找到」。
- 信号格保留（与桌面端一致的语言），弱信号自动变色提示。

### 5. 设备页 · 空状态
- 不是一行「暂无设备」：给结论（已搜完、本网段+已添加网段都没回应）+ 三步自查清单（电脑端打开没、同 Wi-Fi 没、跨网段加网段）+ 双出口（重新搜索=主按钮 / 添加网段），再加配对码兜底入口。每一步都是用户能自己动手解决的，不写「请检查网络设置」这类废话。

### 6. 连接中
- 三步进度明示（已发现 ✓ → 身份确认 ✓ → 建立音频通道…），让等待有预期；超过 10 秒无回应自动转连接失败页（原型目录可直达），不再无限转圈。取消随时可退。

### 7. 连接失败（新增，可恢复）
- 人话结论「电脑没有回应」+ 最可能的两个原因（路由器设备隔离、防火墙拦首次连接），不出现错误码。
- 三个恢复动作按概率排序：再试一次（主）/ 换一台 / 去设置检查网段。页脚安抚：配对信息都还在，不用重新配对。

### 8. 配对确认 / 输配对码
- 确认页把「核对两边数字一致」讲成一句人话问题（电脑屏幕上也显示这串数字吗？），6 位码用大号等宽分格显示；「以后自动连接」默认开并写明含义。
- 输码页保留现版能力，补齐跨网段可用的说明（输码不依赖同网段广播）。

### 9. 会话页（推流中）
- 顶部状态条：推流中（呼吸点）+ 已连接时长；英雄卡：电脑名、IP/采样率/传输、延迟徽章、四格关键指标（丢包/抖动/缓冲/码率）——把现版一整行占位文本（tvStats「丢包 --% · 抖动 -- ms」）拆成可读的仪表。
- **通道开关 FB-9 落地**：开 = 绿色渐变填充 + 白钮右位 + 卡片绿描边 + 绿色文字「已开启 · 正在发送/播放」；关 = 灰轨 + 灰钮左位 + 整卡降透明 + 灰字「已关闭」。颜色、位置、文字、明暗四重区分，色盲或远看都不会误判。整卡头部可点（≥48dp），开关本体 56×32。
- 电平条沿用桌面端 24 段格（绿→黄→红），与桌面端同一视觉语言；音量滑杆、路由入口（整行 ≥54dp）都在会话页内，不用跳页。
- 断开是明确的危险色按钮，按钮下注明「60 秒内自动重连」，降低断开的心理成本。

### 10. 守卫暂停态（FB-8）
- 不再是一行小字备注（现版 tvLoopGuardNote）或红色报错横幅：独立的琥珀色说明卡——先说发生了什么（扬声器声音被麦克风收回去会绕成回声/啸叫）、我们做了什么（只暂停这一路）、没受影响的是什么（麦克风那一路照常）。
- 一键「恢复发送」是主按钮；次按钮「怎么避免再暂停？」展开人话建议（戴耳机/调低音量/离远点）。扬声器通道卡同步呈「已暂停 · 防回环保护中」状态且开关锁定，避免用户在卡上反复戳开关却不知道为什么没声音。

### 11. 断线重连（新增）
- 顶部琥珀横幅 + 旋转指示明示「正在自动重连（第 N 次）」，会话卡保留但降透明——用户知道东西没丢；文案承诺 60 秒内恢复原样（开关/音量保持）。「立即重连一次」与「结束并返回」两个出口都在。

### 12. 输出路由（底部弹层）
- 扬声器/听筒/蓝牙耳机三行各带一句后果说明（扬声器会注明「可能触发防回环暂停」，蓝牙注明「不会触发回环」），选中打勾，点完即关并 toast 确认。现版是设置页里的一组单选钮，连接中改路由要退出会话翻设置——新版在会话页一键直达。

### 13. 设置页
- 按「连接 / 音频 / 跨网段搜索 / 应用」分组卡片，全部行高 ≥56dp；重连方式用分段控件（每次询问/总是自动/从不自动）并注明短时掉线不受影响。
- 跨网段：网段以标签呈现，可删（×）可加（弹层输入前三段并举例 192.168.99.17 → 填 192.168.99），文案说清「当前网段自动搜、不用加」。
- **更新区 FB-10 落地**：只有「当前版本 + 检查更新按钮」，页脚明说「不需要、也没有地方填写任何地址」——把产品决策写进界面，杜绝旧 Muse 地址再以任何形式露面。
- 现版设置是 450 行单覆盖层、六组单选钮的表单堆叠；新版每组只留真正影响行为的项，麦克风灵敏度/降噪模式等低频项收进二级行（原型以「麦克风模式」行示意）。

### 14. 更新流程（底部弹层，五态完整）
检查中（转圈+在连官方发布页）→ 发现新版（版本号、包大小、更新要点列表、覆盖安装保留设置配对的承诺、立即下载/稍后再说）→ 下载中（进度条+百分比+可取消）→ 已是最新（绿勾+当前版本即官方最新）→ 失败（人话原因「请求超时」、明确「不影响正在使用中的连接」、重试）。下载完成 toast 告知并回写设置页版本号。

## 三、动效与状态过渡规范（落地时按此实现）

| 过渡 | 动效 | 时长/曲线 |
|---|---|---|
| 页面切换 | 新页自右 16px 淡入滑入 | 260ms，cubic-bezier(.3,.8,.35,1) |
| 底部弹层 | 自底部上滑 + 背景压暗 | 260ms，同上 |
| 搜索中 | 雷达三环依次扩散（2.6s 循环）+ 骨架屏流光（1.4s） | 持续，直到出结果 |
| 连接中 | 步骤逐项打勾，当前步描边高亮；成功后整页过渡到会话页 | 握手完成即切 |
| 开关切换 | 钮滑动 + 轨道变色 + 电平区淡入/淡出 | 180ms |
| 守卫触发 | 说明卡自会话页顶部滑入（琥珀），不打断麦克风通道 | 260ms |
| 状态呼吸点 | 已连接绿点 2s 脉冲 | 持续 |
| 欢迎页声波 | 五柱律动（1.1s 交错） | 持续 |

原则：动效只表达状态变化，不做纯装饰；所有持续动画在页面不可见时停（省电）。

## 四、现版 UI 的具体问题（本次逐项修掉）

1. **单页巨无霸**：1551 行布局一页堆到底，设备、通道、设置入口在视觉上没有层级，用户找不到「下一步点哪」。
2. **四种横幅可叠罗汉**：重连/自动连接/回归询问/耳机提示四个横幅同时存在时会把内容顶到屏幕外，且每种都要用户读一遍才知道要不要管。
3. **通道控件不一致**：麦克风/扬声器用复选框、回声消除用开关，同一页三种交互语言；且开关开/关颜色无区别（FB-9 原案）。
4. **守卫提示无出口**：回环守卫触发后只有一行小字（tvLoopGuardNote），没有「为什么没声音」的人话解释，也没有恢复按钮（FB-8 原案）。
5. **更新地址暴露**：设置里有可编辑的更新地址输入框（etUpdateUrl），存量旧值还会盖掉新默认（FB-7/FB-10 原案）。
6. **状态靠一行占位文本**：连接质量挤在 tvStats 一行「丢包 --% · 抖动 -- ms · 缓冲 -- ms」里，无层级、无单位强调。
7. **空状态等于没状态**：找不到设备只有 tvNoDevice 一行字，没有自查路径也没有下一步按钮。
8. **发现是独立覆盖层**：附近发现（overlayDiscover）与主页脱节，搜不到时用户被卡在覆盖层里。
9. **设置是表单不是产品**：六组单选钮平铺（含输出路由、麦克风模式、灵敏度、降噪、输入设备），无分组说明、无后果提示，改路由还要先进设置。
10. **没有首启流程**：装完直接进主页，权限在用到时被系统弹窗突袭申请，没有任何「为什么」的铺垫。

## 六、开放问题（请 Gray 定夺，最多 3 个）

1. **守卫恢复策略**：防回环暂停后，是保持「必须手动点恢复发送」（本稿方案，更可控），还是「检测到回环消失（如戴上耳机）自动恢复」（更无感，但可能反复横跳）？
2. **会话页要不要底部标签栏**：本稿是单主线（设备页→会话页），没有底部「设备/设置」标签栏；设置靠右上角齿轮进。是否接受，还是希望设置常驻底部标签？
3. **跨网段标签的详细程度**：本稿显示「跨网段 · 192.168.99.x」；是否希望直接显示完整 IP（更工程）还是只显示网段（更干净）？

## 七、v2 手势与快捷导航层（preview_android_v2.html）

v1（已归档至 `archive/preview_android.html`）经 Gray 确认「OK」，但提出：不能只依赖 UI 点击，要按正常 App 的标准加入手势与快捷返回。v2 在 v1 全部界面与文案不变的前提下，只加一层手势导航——手势是**多一条路，不是替换**：左上角返回按钮、弹层取消按钮等显性入口全部保留。

原型里四种手势全部可实作：评审时请在手机框里真拖、真滑、真长按，不要只看目录。

### 7.1 手势地图

| 手势 | 作用范围 | 动作 | 兜底（显性入口） |
|---|---|---|---|

### 7.2 逐项说明

**边缘右滑返回（predictive-back 式）**
- 拖动时页面实时跟手（位移 ×0.92 + 渐隐），左边缘浮出返回箭头气泡，随进度放大滑入；松手位移 > 84px 才触发返回，不足则回弹——和安卓 14+ 预测性返回的观感一致，不是「滑完才跳」。
- 可发现性三件套：① 进入子页面时左边缘出现一条半透明的渐变手势提示带（主页不显示）；② 首次进入子页面时底部浮出一句教练提示「从左边缘向右滑，也能返回上一级」，3 秒自动收起，只出现一次；③ 手机框底部有系统手势条示意。
- 内容区右滑是同等能力的第二通道：很多用户不会精准摸边缘，内容区起手右滑同样返回（冲突规则见 7.3）。

**系统返回语义（写死，不许落地时自由发挥）**
1. 有底部弹层打开 → 只关弹层，不动页面；
2. 否则回上一级（与左上返回按钮、边缘滑完全同一条栈）；
3. 栈空（在主页）→ App 切后台，**不结束会话**：原型里会看到桌面示意 + 常驻通知「听说 · 正在推流 — 点按回到 App」，点通知或图标回来，会话计时一直在走、没有断。这是前台服务产品的标准行为，文案已写进原型（后台提示条明说「推流不会中断」）。
- 导航改为真栈：前进压栈、「连接中 → 会话」是替换（返回不许落回连接中）、断开/结束类动作回主页即清栈；左侧目录是评审工具，直达任意屏时清栈，不算 App 内导航。

**下拉刷新**
- 只在设备页三态、且列表已滚到最顶时接管下拉；拉动时内容跟手下移，顶部药丸提示从「下拉重新搜索」变为「松开重新搜索」（阈值约 132px 原始位移），松手后走完整流程：搜索中（雷达）→ 回列表 → toast。
- 会话页、设置页不做下拉刷新——没有可刷新的列表就不给假手势。

**长按快捷操作（顺带解决设备命名痛点）**
- 长按时卡片先给按压反馈（描边变绿 + 微缩放），满 480ms 弹层打开，随后的那次点按被吞掉，不会误触连接。
- **重命名是真功能**：弹层内输入新名 → 保存后卡片立即改名并 toast。机器名（DESKTOP-6IGKI7F 一类）对不上号是已知痛点，改名入口就放在离设备最近的地方，不用进设置翻。
- 置顶：卡片移到本组最前并挂「置顶」标签，再长按可取消置顶；忘记此设备：删卡 + toast 明示「下次连接需重新配对」。

### 7.3 冲突规则（原型已按此实现，落地照抄）

| 冲突 | 规则 |
|---|---|
| 横滑 vs 音量滑杆 | 起手落在 `input[type=range]` 上时手势层完全不接管，滑杆优先（会话页调音量不会被滑返回） |
| 横滑 vs 纵向滚动 | 起手移动 9px 内按主导轴判定：纵向占优立即让给滚动，横向占优才进跟手拖动；判定后不反悔 |
| 横滑 vs 弹层 | 弹层打开时内容区右滑禁用；边缘右滑仍可用，但语义是系统返回第一级——只关弹层 |
| 下拉 vs 纵向滚动 | 仅当 `scrollTop = 0` 且继续下拉时接管；列表中部下拉永远是滚动 |
| 长按 vs 滑动/滚动 | 按住后移动 > 10px 即取消长按计时，不误弹菜单 |
| 长按 vs 点按 | 长按触发后置标志吞掉紧随的 click，连接动作不会被误触 |
| 手势 vs 后台态 | 已切后台时原型手势层整体停用，点通知/图标先回 App |

### 7.4 落地映射（安卓实现一一对应，构建阶段无歧义）

| 原型行为 | 安卓实现 |
|---|---|
| 边缘右滑跟手返回 + 箭头气泡 | 系统预测性返回：`AndroidManifest` 开 `android:enableOnBackInvokedCallback="true"`，用 `OnBackAnimationCallback`（Android 14+）拿 `BackEvent.progress()` 驱动页面位移/箭头；低版本走 `OnBackPressedDispatcher` 的普通返回（无跟手，有过渡动画即可） |
| 系统返回三级语义 | `OnBackPressedDispatcher` 按优先级注册回调：弹层（BottomSheetBehavior 可取消）> 导航栈（NavController.popBackStack）> `moveTaskToBack(true)` 切后台；**禁止**在主页返回时 finish 会话 Activity/停前台服务 |
| 切后台保会话 | 前台服务（现有 BridgeService）+ 常驻通知（点按 PendingIntent 回 App），返回切后台只是任务栈行为，与服务生命周期解耦——现有架构已满足，只需保证返回路径不调 stopService |
| 下拉刷新 | 设备页用 `SwipeRefreshLayout`（或 Compose `pullRefresh`），刷新动作直接复用现有发现流程（广播 + mDNS + 跨网段单播探测），完成回调停指示器 |
| 长按快捷操作 | RecyclerView/Compose 列表项 `setOnLongClickListener` / `combinedClickable` 的 onLongClick → 同一 BottomSheet；重命名写本地设备别名字段（与桌面端改名互不影响，只存手机本地，和原型文案一致） |
| 栈式导航 | 单 Activity + Navigation Component：主页（设备页）为 startDestination，连接中设 `popUpTo` 替换语义，断开动作 `popUpTo(主页, inclusive=false)` 清栈——与原型 go/jumpTo/systemBack 三个函数一一对应 |
| 教练提示与手势带 | 首次进入子页时一次性提示（SharedPreferences 记已读），手势带可做成主题级装饰、主页不显示；均为锦上添花，系统手势本身不需要教学也能用 |

### 8.2 展开 / 折叠规则（原型可实作）

- **手动展开**：点紧凑条展开；同一时刻至多一张手动展开 — 打开另一张（含动态演示位处于未连接态时）会先收起前一张（220ms 同步动画）。
- **自动展开**：进入连接中 / 已连接 / 守卫暂停 / 重连窗口由状态驱动展开，不进手动展开集。
- **已连接不可手动折叠**：点标题只提示原因；断开（点卡内「断开」）后**自动折回紧凑条**，并 toast 明示「设备已自动收起为紧凑条」。
- **完整生命周期演示**：密度屏第一台 DESKTOP-6IGKI7F 可走通「已连接整卡 → 断开 → 自动收成紧凑条 → 点开（手动展开）→ 连接 → 连接中整卡（约 1.8s）→ 已连接整卡」，连接中可取消（回紧凑条）。
- **动画**：展开/折叠统一 220ms，曲线 cubic-bezier(.3,.8,.35,1)（高度 max-height + 透明度 + 标题行箭头旋转），与 §A.1.7 规格一致。
- **长按**：v2 长按快捷菜单（重命名 / 置顶 / 忘记）在密度屏对整卡与紧凑条同样生效（§A.2.5：chip 长按直接弹菜单，不先展开）；置顶/忘记作用于整行（slot）。
- 紧凑条状态**不用颜色单独说话**：状态点之外恒有文字（在线 / 未上线 / 推流中 / 连接中），守 §A.2.3 的冗余要求。
