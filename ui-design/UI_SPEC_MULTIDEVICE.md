# 声音接力 SoundRelay — UI 规格扩展 v2：多电脑 + 自动激活

> 这是 `UI_SPEC.md`（v1）的增量规格，只写新增/变化的部分；未提到的 token、字号、圆角、间距、电平表、延迟配色规则全部沿用 v1，不再重复定义。
> 冲突时以本文件为准的只有三处：① 首页由「单台 Hero」改为「总览条 + 设备卡列表」；② v1 的设备区（发现列表）并入本文件的设备卡体系；③ 主按钮语义变化（见 §2.3）。

## 0. 概念与规则（先定死，UI 只是它的呈现）

| 概念 | 定义 | UI 后果 |
|---|---|---|
| 配对（Paired） | 手机与某台电脑互相保存了对方身份（设备 ID + 密钥指纹）。扫码或配对码完成一次，永久记住，直到用户删除 | 设备进入「我的电脑」区，跨重启保留 |
| 在线（Online） | 已配对设备正在同一局域网/USB 上广播心跳（≤3 秒一次），手机能听见 | 卡片点亮，可连接/推流 |
| 自动连接（Auto-connect） | 某台已配对设备的专属开关。开着时：它一上线，手机自动连接并恢复它上次的通道开关状态、自动开始推流，全程不用点 | 开关在离线时也可改、且必须可改（见 §3.3） |
| 扇出（Fan-out） | 手机麦克风同一路声音，同时发给所有「麦克风发送」开着的在线电脑 | 总览条显示「麦克风 → N 台电脑」 |
| 混音（Mix） | 多台电脑的声音在手机端混合后从扬声器播出，每台有独立音量/静音 | 每张卡有自己的音量条；总览条显示「扬声器 ← M 台电脑混音」 |
| 未配对发现（Discovered） | 广播能听见、但没配过对的电脑 | 只出现在「新设备」区，只有「配对」动作，没有任何通道开关 |

排序（「我的电脑」区内，固定）：推流中 > 已连接待机 > 已配对离线；同档内按最近连接时间倒序。在线状态变化时列表重排，但**正在被手指按住/刚操作完 1 秒内的卡片不移动**（防误触，实现上重排加 300ms 淡入即可，不做位移动画）。

单 Activity、单页纵向滚动，骨架沿用 v1 §3.1，只换中段：

```
ScrollView (bg)

   │    ├─ 扬声器电平条 meterSpk（混音后）    尾值 -18 dB
   │    └─ 统计行: 麦克风 → 2 台 · 扬声器 ← 2 台混音 · 丢包取最差一路 0.3%
   ├─ 区标题行: 我的电脑                    [添加电脑 +]（文字按钮 → 展开 §4 入口）
   ├─ 设备卡 ×N（listPc 容器内逐个生成，见 §2）

   ├─ 添加电脑卡（常驻，bg_card 虚线描边版 bg_card_dashed）

   │    副文案: 电脑端点「显示配对二维码」，扫一下就记住这台电脑
```

- 总览卡只在「至少 1 台推流中」时是 v1 的完整 Hero；无人推流时收起为一行摘要条（高 56dp，`bg_card`）：左侧状态点 +「1 台在线 · 未推流」+ 右侧文字按钮「全部开始」。电平条与统计行 `gone`。**不要**在无推流时留一个空 Hero 占位。
- 全局主按钮 `btnStart`（v1 的三态大按钮）在多设备下**取消**：开始/停止下放到每张设备卡（见 §2.3）。原 `btnStart` 所在位置改为「全部停止」危险文字按钮，且仅当 ≥2 台推流中时出现。构建 Agent 注意：`btnStart` 的全局启停逻辑废弃，id 可保留给「全部开始/全部停止」复用，不要再绑单台逻辑。

### 1.1 设备卡通用结构（在线卡，约 148dp）

```
┌──────────────────────────────────────────┐  bg_card / 状态变体见 §3
│ ▌🖥 QI-PC            [LIVE 18ms·流畅]    │  左 3dp 状态竖条（仅推流中，accent）
│   Windows · 192.168.1.20 · WiFi          │  名称 h2 16sp；副行 caption text2 等宽 IP
│   ● 已自动连接 · 自动连接 [开关 swAuto]  │  自动连接行：bodyS + 右侧小开关
│  ──────────────────────────────────────  │  分隔线 stroke
│   麦克风 → 这台电脑        [开关 swMic]  │  开=accent 轨（同 v1 通道卡规则）
│   电脑声音 → 手机扬声器    [开关 swSpk]  │  开=sky 轨
│   这台的音量 [────●──] 70% [🔊/🔇]      │  仅 swSpk 开时可用，sky 着色（同 v1 seekVolume 规则）
└──────────────────────────────────────────┘
```

- 卡内不再放电平条（电平只在总览卡，避免 N 张卡 N 条表乱跳）；卡内状态靠徽章 + 开关 + 竖条表达。
- 音量行：`SeekBar`（每卡一个）+ 右侧静音切换小按钮（图标按钮 40dp，静音时图标变 `error` 斜杠喇叭、滑杆变 `text3` 灰、数值显示「静音」）。静音只哑这台电脑的声音，不关 `swSpk`（恢复时音量还在）。
- 长按卡片 → 底部弹出菜单（框架 `PopupMenu` 即可）：重命名 / 忘记这台电脑 / 查看配对信息。非常规操作不占卡面。

## 2. 每卡控件语义

### 2.1 开关清单（每张已配对卡固定 3 个 Switch + 1 个 SeekBar + 1 个静音钮）

| 控件 | id 建议 | 默认 | 说明 |
|---|---|---|---|
| 自动连接 | `swAuto` | 配对完成时默认开 | 见 §0；离线可改；关掉后该设备上线只显示「在线」，不自动连 |
| 麦克风发送 | `swMicToPc` | 开 | 这台电脑能不能收到手机麦克风（扇出成员） |
| 扬声器接收 | `swSpkFromPc` | 开 | 这台电脑的声音进不进手机混音 |
| 本机音量 | `seekPcVolume` | 上次值，初始 70% | 只影响这台在混音里的音量，0–100 |
| 静音 | `btnMutePc` | 关 | 与音量并存，见 §1.1 |

### 2.2 状态持久化

每台设备的 `swAuto / swMicToPc / swSpkFromPc / 音量 / 静音` 全部按设备 ID 存 `SharedPreferences`（一个 JSON 即可）。自动连接恢复的就是这组值——「激活」的定义就是：连接 + 按存好的开关开始推流，不需要任何确认弹窗。

### 2.3 卡内主动作（右下角文字按钮，随状态变）

| 状态 | 按钮文案 | 行为 |
|---|---|---|
| 在线 · 未连接（自动连接关时） | 连接 | 只连这台 |
| 已连接 · 待机 | 开始推流 | 按卡上开关推流 |
| 推流中 | 停止 | 只停这台，不影响其他电脑 |
| 离线 | （无按钮） | 位置留给「上次连接 {时间}」文字 |

## 3. 三种设备状态的精确视觉（硬规则）

三种状态必须**不靠读文字也能一眼分清**：靠底色、饱和度、状态点、徽章四通道冗余编码。

### 3.1 发现 · 未配对（「新设备」区，行式不是卡式，高 64dp）

| 元素 | 值 |
|---|---|
| 容器 | `bg_card`（`surface`），描边用虚线版 `bg_card_dashed`（stroke `strokeHi`，dash 6/4）——虚线 = 「还没建立关系」 |
| 图标 | 电脑图标放 `surfaceIn` 圆角块内，图标色 `text2` |
| 名称 | `body` 粗，`text1`；副行 caption `text2`：「{Windows/Linux} · 未配对」 |
| 状态点 | 无点（或 6dp 空心圆 `strokeHi`）——不许用 accent，会与在线混淆 |
| 右侧 | 文字按钮「配对」（`sky` 色，描边按钮 `bg_btn_outline_sky`） |
| 开关/音量 | **全部不出现**。未配对就没有通道概念 |
| 点整行 | 同「配对」按钮，进 §4 配对流 |

### 3.2 已配对 · 在线（分待机/推流两档，同一张卡）

| 元素 | 待机（已连接未推流） | 推流中 |
|---|---|---|
| 容器 | `bg_card` 但底色换 `surfaceHi` 版 `bg_card_online`，描边 `strokeHi` | 同左 + 左侧 3dp `accent` 竖条（`bg_card_live` 用 layer-list 叠竖条） |
| 状态点 | 8dp `accent` 实心（不闪） | 8dp `accent` 呼吸闪烁（同 v1 LIVE 点动画） |
| 徽章 | `bg_chip` 中性：「已连接 · 待机」`text2` | 延迟徽章（v1 硬规则配色）：`{n} ms · 流畅/一般/偏高`，底色对应 `accentDim/warn 淡底/errorDim` |
| 副行 | `{OS} · {IP} · {WiFi/USB}`，`text2` | 同左 |
| 开关 | 全部可操作，轨色同 v1（mic=accent / spk=sky / auto=accent） | 同左；推流中关 `swMicToPc` 只停这一路扇出 |
| 自动连接行 | 若为手动连接且 `swAuto` 开着被触发过，显示「● 已自动连接」`accent` 小字（见 §5） | 同左 |

未连接但在线（`swAuto` 关、上线被看见但没连）：底色用普通 `surface`（不升 `surfaceHi`），状态点 `accent` 但徽章是中性「在线 · 未连接」，主动作按钮「连接」。与待机档的区别只在底色与徽章，不许只差一个字。

### 3.3 已配对 · 离线（灰态卡）

| 元素 | 值 |
|---|---|
| 容器 | `bg_card`，整卡 `alpha 0.55`（框架里对卡根 View `setAlpha(0.55f)` 一行搞定，子控件不用逐个改色） |
| 状态点 | 8dp `text3` 实心 |
| 名称 | 保持 `text1`（靠整卡 alpha 自然变灰，不要单独改色，否则 alpha 叠加后太淡） |
| 徽章 | `bg_chip`：「离线」`text2`；右侧 caption：「上次连接 {今天 14:02 / 昨天 21:14 / 11-12 09:30}」`text3` 等宽 |
| 延迟徽章 | 不出现（没有当前延迟，显示 `-- ms` 也多余，整块 `gone`） |
| `swMicToPc` / `swSpkFromPc` / 音量 / 静音 | 全部 `enabled=false` 呈灰，但**值保持原样可见**（用户要能看出「它回来后会按这个状态激活」） |
| `swAuto` | **唯一保持可操作的控件**，且不受整卡 alpha 影响——实现上把自动连接行放在卡内一个不跟随 alpha 的子容器里，或离线卡不用整卡 alpha、改为逐元素灰化但跳过这一行。二选一，验收标准只有一个：离线时能开关自动连接，且它看起来是亮的 |
| 主动作按钮 | 无，见 §2.3 |

## 4. 配对流（扫码为主，配对码兜底）

全部在本 Activity 内以全屏覆盖层（`FrameLayout` overlay，默认 `gone`）实现，不新建 Activity，不跳系统页。

### 4.1 入口

两个入口等价：「添加电脑卡」的两个按钮；「新设备」区某行的「配对」——区别是后者已知道目标设备，扫码/输码成功后要校验扫到的就是点的那台，不一致时提示「扫到的不是这台电脑，已按扫到的设备配对」（不报错、不中断）。

### 4.2 扫码屏 `overlayScan`

```
┌──────────────────────────────────┐
│ ← 扫码配对              [🔦 手电] │  顶栏：返回 + 标题 h2 + 手电开关
│                                  │
│      ┌ ─ ─ ─ ─ ─ ─ ┐             │  取景框 248×248dp 居中，
│      │             │             │  边框 bg_qr_frame：2dp accent 圆角 24，
│      │  (相机画面) │             │  四角加粗 L 形角标（layer-list 或自绘 View）
│      │  ─ ─ ─ ─ ─  │ ← 扫描线    │  2dp accent 横线，上下扫动动画（ObjectAnimator 循环）
│      └ ─ ─ ─ ─ ─ ─ ┘             │
│   对准电脑屏幕上的二维码          │  body，text1 居中
│   电脑端打开声音接力，点「显示配对     │  bodyS text2 居中
│   二维码」即可                    │
│                                  │
│   没有二维码？输入配对码 →        │  底部文字按钮 sky → §4.4
└──────────────────────────────────┘
```

- 背景：相机预览全屏 + 四周压暗（取景框外 `#0B0E13` 78% 透明黑遮罩，用 4 块 View 拼，不要用复杂 Drawable）。
- 实现注记（框架限定）：无 AndroidX → 无 CameraX。用 `camera2` + `TextureView` 预览，解码用 ZXing core（纯 Java，可直接打进 APK，无原生依赖）；只认声音接力自己的码（内容前缀校验），扫到别的码时取景框闪 `error` 边 + 文案「这不是声音接力的配对二维码」，不退出。
- 权限被拒：覆盖层换空态「需要相机权限才能扫码」+「去设置开启」按钮 + 底部保留「输入配对码」入口（配对码流不依赖相机，必须始终可达）。

### 4.3 确认屏 `overlayConfirm`（扫码/输码共用，配对成功的最后一道闸）

```
┌──────────────────────────────────┐
│ 找到这台电脑                     │  h1
│ ┌──────────────────────────────┐ │
│ │ 🖥 QI-PC                     │ │  bg_hero 卡：名称 h2 + 副行
│ │ Windows · 192.168.1.20       │ │  {OS} · {IP} · {WiFi/USB}
│ │                              │ │
│ │ 核对验证码                   │ │  caption text2
│ │  4 8 2 9 1 6                 │ │  display 28sp 等宽，字距拉开
│ │ 与电脑屏幕上显示的 6 位数     │ │  bodyS text2
│ │ 一致再点配对                  │ │
│ └──────────────────────────────┘ │
│ 自动连接 [开关，默认开]          │  body + swAutoConfirm
│ 这台电脑以后出现在同一网络时，   │  bodyS text2
│ 自动连接并按上次的设置开始推流   │
│ [        确认配对              ] │  主按钮 bg_btn_primary
│ [            取消                ] │  文字按钮 text2
└──────────────────────────────────┘
```

- 验证码不一致怎么办：不提供「不一致」按钮（多一个按钮多一次误触）；用户自己取消即可。文案已说明「一致再点配对」。
- 点「确认配对」→ 按钮转「配对中…」禁用态 → 成功进 §4.5，失败（超时/对方拒绝）按钮恢复 + 顶部 `errorDim` 条「配对失败，电脑那边没有确认，请重试」。

### 4.4 配对码兜底屏 `overlayCode`

```
┌──────────────────────────────────┐
│ ← 输入配对码                     │
│ 电脑端打开声音接力，点「显示配对码」，│  bodyS text2
│ 把 6 位数字输进来                │
│                                  │
│  [ 4 ][ 8 ][ 2 ][ 9 ][ 1 ][ 6 ]  │  单个 EditText 冒充 6 格：
│                                  │  monospace 28sp、letterSpacing 0.5、
│                                  │  底 bg_input_code（surfaceIn+圆角14），
│                                  │  inputType=number，maxLength=6
│ 输入后会自动查找这台电脑…        │  未满 6 位时 caption text3
│ [        查找并配对            ] │  满 6 位才 enabled（主按钮）
│ 用扫码更快 → 扫码配对            │  文字按钮 sky → §4.2
└──────────────────────────────────┘
```

- 输满 6 位自动提交一次（不用等点按钮，按钮是给不放心的用户留的）。
- 错误态：输入区描边变 `error` + 下方 `error` 文案，按错因换文案（见 §7 表）：码不存在/已过期（配对码 10 分钟有效）/同码已配过（直接提示「这台电脑已经配对过了」并定位到那张卡，高亮 1 秒）。

### 4.5 配对成功（不做独立成功页）

确认屏直接收起，回首页：新卡插入「我的电脑」区首位并闪一次 `accent` 描边（`strokeHi→accent→strokeHi`，600ms），同时顶部出一条 `accentDim` 横条（复用 `bannerAuto`）「✓ 已配对 QI-PC，自动连接已开启」。3 秒自动消失。不用对勾动画页、不用 Toast 叠加。

## 5. 自动连接发生的瞬间（克制呈现，硬性要求）

原则：**自动的事不要打断人**。不弹窗、不跳页、不响铃、不震动。用户正在看别的 App 时，只发一条低优先级静默通知（见下）。

时间线（已配对设备上线被发现 → 激活完成，通常 1–3 秒）：

| 时刻 | 界面发生什么 |
|---|---|
| t0 发现心跳 | 该卡从离线灰态淡入在线底色（alpha 0.55→1，200ms），徽章「离线」→「在线 · 连接中…」（`warn` 点） |
| t1 连接+恢复开关+开始推流 | 卡升为推流档：左竖条出现、状态点开始呼吸、延迟徽章出现；卡内自动连接行出现小字「● 已自动连接 · 刚刚」`accent`（保留到用户下次手动操作该卡为止） |
| t2 横条 | `bannerAuto` 从 Header 下方滑入（translationY + alpha，250ms）：`accentDim` 底、圆角 14、高 44dp：左 ✓ 图标（accent）+「已自动连接 QI-PC · 18 ms」+ 右侧「撤销」文字按钮（点了只断这一台，不关它的 `swAuto`，文案别写「关闭自动连接」，避免误伤设置） |
